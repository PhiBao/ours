# Ours

Two people who share money each answer six open questions alone, and then open the same
page: whether they are actually arguing about the same thing.

```
pnpm install
cp .env.example .env      # add a key from https://console.typesafe.ai/keys
pnpm dev                  # http://localhost:3000
```

**To try the whole loop** open the site in a normal window and a private window, join both
with the same code, and answer as each person. The second submission builds the page.

**Scripts**

| | |
|---|---|
| `pnpm seed` | The measurement and composition pipeline on a real pair, plus the three controls |
| `pnpm e2e` | The full loop over HTTP, and a direct read of the database afterwards |
| `pnpm capture` | 15 screenshots of the whole journey, in `demo/shots/` |
| `pnpm video` | The demo recording, in `demo/` |
| `pnpm typecheck` | `tsc --noEmit` |

## What it is

A proof of concept built for Devpost's Build With AI: Basics. The planning that produced
it is in `devpost/` — `scope.md`, `prd.md`, `spec.md`, and the build `checklist.md`, all
generated by running the Devpost Learn Skill Pack.

**The idea.** Every existing product in shared finances answers an information problem and
asks you to solve a trust problem to get at it: someone has to link their accounts or open
up first, and going first feels like conceding, so it never happens. Both people argue
from partial pictures forever. Ours inverts it — each partner answers alone, the reveal
does not exist until both are in, and neither of them sees the other's words.

## How it works

Three layers, deliberately kept apart:

- **`src/lib/questions.ts`** — the measurements. Narrow, typed questions asked of each
  person's answers alone, then of the two answers together. Every question is phrased as
  the specific claim the reveal will actually make.
- **`src/lib/derive.ts`** — round one per person, round two about the pair, then
  thresholds. Produces numbers only.
- **`src/lib/compose.ts`** — a pure function with no imports and no I/O. Numbers in,
  sentences out. **Every English sentence on the reveal comes from this file.**

There is no language model anywhere in the product. TypeSafe's System One returns
calibrated probabilities; code decides what they mean and writes the sentence. That is why
the reveal can make a strong claim: every line on it is a claim that was actually
measured, and the numbers are visible underneath.

### Why narrow questions

An earlier version asked one broad question — *are these two people worried about the
same thing?* — and it was unreliable: it returned 0.37 confidence and disagreed with
itself across runs about people whose answers plainly disagreed. Asking instead *is one of
them driven by wanting to enjoy money while the other wants certainty?* returns 0.85 on
the target pair against 0.04 on a deliberately healthy, aligned pair. The product only
says what it asked about, and a page comes back nearly empty when it cannot stand behind
anything.

### The privacy claim

`app/api/reveal/route.ts` derives the page, and `storeRevealAndShred` in `src/lib/db.ts`
writes it and clears both people's answers in one transaction. By the time the request
returns, the words are not in the database. `pnpm e2e` checks this directly — it proves
`raw_answers` is `NULL` for both people while `reveal_json` is populated.

The words a person sees under an expanded finding come from their own browser, not the
server. Their own answers were never shared in the first place, which is why the promise
survives.

The commitment hash shown before sealing is tamper-evidence for the person who wrote the
answers. It is not a zero-knowledge proof against a hostile server, and the product does
not claim it is.

## What is real

- All measurements are real calls against the TypeSafe API. Responses are cached on disk,
  keyed by a hash of the request, so `pnpm e2e`, `pnpm capture` and `pnpm video` make no
  network call on a second run and produce identical numbers. The demo can be recorded
  with the network switched off.
- The demonstration control at `/demo` derives live from written pairs. A real pair's words
  are destroyed the moment its page exists, so there is nothing real to re-derive — which
  is why the control says on screen that it is not a product feature.
- Storage is Node 22's built-in `node:sqlite`, so `pnpm install` compiles nothing.

## What is not built

No bank connections. No accounts. No notifications. Past reveals and history. Voice input.
See `devpost/prd.md > Non-Goals` for each with its reason.

## Stack
